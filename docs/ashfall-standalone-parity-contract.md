# Ashfall Standalone Parity Contract

## Purpose

This document freezes the machine-readable parity contract between the Ashfall module truth (produced by `ECHO-Modules`) and the `ECHO-Standalone-Runtime`. It exists so that the runtime can report **exactly which IDs and domains are missing** instead of emitting vague "content missing" errors.

The companion file [`ashfall-standalone-parity-checklist.json`](ashfall-standalone-parity-checklist.json) is the canonical checklist consumed by validators. It is generated from `docs/echo/standalone/ASHFALL_PARITY_MATRIX.md` and checked into version control.

## Scope

This contract covers the Ashfall runtime module closure required for standalone beta readiness:

- **Blocks** — all `echoashfallprotocol:*` and `echoterminal:*` block IDs.
- **Items** — all Ashfall item IDs including spawn eggs, tools, consumables, components, and data logs.
- **Creative Tabs** — module-provided creative inventory tabs and their item membership.
- **Recipes** — shaped/shapeless/cooking/machine recipes.
- **Loot Tables** — block/entity/container loot.
- **Entities / Mobs** — hostile, neutral, NPC, drone, and boss entity IDs.
- **Spawn Rules** — biome/tag constraints, weights, group sizes, safe zones, cooldowns.
- **Biomes & Regions** — surface blocks, generation blocks, effects, tags.
- **Structures & Features** — placement hints, template pools, biome tags.
- **Sound Events** — UI, ambient, and entity audio cues.
- **Missions & Objectives** — mission IDs, objective sequences, prerequisites, rewards.
- **UI Routes** — Terminal, Lens, Index, HUD, HoloMap, ScreenCore surfaces.

## Status Values

For every required ID the runtime reports one of:

| Status | Meaning |
| --- | --- |
| `required` | Listed in the parity checklist; expected to be present. |
| `present` | Found in the installed module Content Graph with complete metadata. |
| `partial` | Found, but missing required metadata (e.g., entity has no texture path). |
| `missing` | Not found in the Content Graph at all. |
| `unsupported` | Found in the Content Graph but marked `blocked`/`unsupported` in the `echo_runtime_standalone` export plan. |

## Exit Gate

A strict-pack boot is **BLOCKED** when any required domain has:

- zero nodes of the required node kind(s), **or**
- any `missing` required ID, **or**
- any `unsupported` required ID, **or**
- any `partial` required ID whose missing metadata is flagged as beta-critical.

Dev mode and safe mode continue with diagnostics but do not block.

## Required ID Sources

1. `docs/ashfall-standalone-parity-checklist.json` — generated from the full Ashfall parity inventory.
2. Per-module `.echo/content-graph/content-graph.json` — generated by `ECHO-Modules/scripts/generate-content-graph.mjs`.
3. Per-module `.echo/content-graph/export-plans/echo_runtime_standalone.json` — generated by `ECHO-Modules/scripts/generate-runtime-export-plan.mjs`.

## Runtime API

The Java contract is loaded by `EchoAshfallParityContract` in `echo-runtime-compat`. It provides:

- `requiredIdsForDomain(String domain)` — list of required canonical IDs.
- `validateReport(Map<String, Object> auditReport)` — returns pass/fail with exact missing/partial/unsupported IDs.
- `missingIds(Map<String, Object> auditReport)` — convenience view of only missing IDs.

## Change Control

When Ashfall adds, removes, or renames content:

1. Update `docs/echo/standalone/ASHFALL_PARITY_MATRIX.md`.
2. Re-run `node scripts/generate-ashfall-parity-checklist.mjs`.
3. Commit the regenerated `docs/ashfall-standalone-parity-checklist.json`.
4. Update the runtime `EchoAshfallParityContract` tests if behavior changes.
